# Query & Retrieval Architecture

*This document defines how the user's knowledge graph is queried. The query layer is built on multi-hop GraphRAG, not flat vector search.*

## Why GraphRAG over Vector RAG?
- Vector RAG retrieves semantically similar nodes but cannot answer temporal or relational questions.
- A query like *"How has this belief evolved over 6 months?"* requires graph traversal (`Episode` → `Pattern` → `Belief v1` → `evolved_from` edge → `Belief v2`).
- GraphRAG combines vector similarity for candidate retrieval with graph traversal for context assembly.

## Query Types
1. **Pattern Query:** "What keeps happening?" → retrieve `PatternNode`s by embedding similarity + recency weight.
2. **Belief Query:** "What do I believe about X?" → retrieve `BeliefNode`s, include version chain.
3. **Temporal Query:** "How has Y changed over time?" → traverse `evolved_from` chains.
4. **Relational Query:** "What's my relationship with [Person]?" → retrieve `PersonEntityNode` + all linked observations.
5. **Counterfactual Query:** "What worked before in this situation?" → traverse causal chains to find positive `OUTCOME` steps.
6. **Decision Support Query:** "I'm facing X now" → retrieve similar past patterns + their resolution causal chains.

## Counterfactual Retrieval
This is the most novel query type in the system.

- User states current `INTERNAL_STATE` (e.g., "overwhelmed by a complex task").
- System embeds this state and retrieves past `EpisodeNode`s with semantically similar `INTERNAL_STATE` observations.
- From those episodes, it traverses causal chains: `TRIGGER` → `INTERNAL_STATE` → `ACTION` → `OUTCOME`.
- It surfaces only chains where `OUTCOME.content` has positive valence AND `OUTCOME.lesson` exists.
- Response format: *"In [episode date], you faced a similar state: [INTERNAL_STATE]. You did [ACTION]. Result: [OUTCOME]. Lesson: [LESSON]."*

**JSON Example of a causal chain retrieval result:**
```json
{
  "query_type": "counterfactual",
  "input_state": "overwhelmed by a complex task",
  "retrieved_chains": [
    {
      "episode_id": "ep_2026_06_11",
      "date": "2025-01-18",
      "chain": [
        {"type": "INTERNAL_STATE", "content": "Mental fog and panic over task breadth"},
        {"type": "ACTION", "content": "Broke task into explicit physical steps, slowed down breathing"},
        {"type": "OUTCOME", "content": "Regained clarity and executed step 1 within 10 minutes", "valence": "positive"}
      ],
      "linked_lesson": "Slowing down physical pace directly regulates cognitive panic."
    }
  ]
}
```

## Context Assembly Strategy
- **Context window budget:** prioritized by `final_score` (cosine similarity × signal_weight × recency_weight).
- **Hierarchy:** Beliefs first, then Patterns, then Episodes (most general to most specific).
- **`signal_strength: CRITICAL` nodes in sensitive domains:** not auto-injected into context. Eligible for injection only if the user explicitly introduces the topic in the current session (see `CRITICAL_DOMAIN_OPENED` in Conversational_RAG_Mode.md).
- **Contextual compression:** retrieved nodes are summarized to key sentences before being injected into the generation prompt.
- **Max context nodes:** 10 nodes total (adjustable), with at least 1 Belief if available.

## Query Feedback Loop
- Every query is logged: timestamp, embedding of query, nodes retrieved, user satisfaction signal (optional: thumbs up/down).
- Nodes retrieved frequently in queries are tagged with a `query_frequency` counter.
- Macroextraction reports surface the top 3 "most queried patterns" as a proxy for what the user is most concerned about.
- High `query_frequency` patterns receive a weight boost in future retrieval (0.1x additive, max 1.5x total from frequency).

## Reflection Prompt Engine (Pre-Capture Intelligence)
- Before each journal session, the system generates 2-3 context-aware questions.
- **Question sources (in priority order):**
  1. Unresolved `OPEN_LOOP` observations (oldest first).
  2. "Disappearing patterns" from last Macroextraction (did they resolve or just go unlogged?).
  3. Recent `SUPPRESSED_EMOTION_SURFACING` observations (unprocessed emotional depth).
  4. Active `CONTRADICTION` nodes (held tension needing articulation).
- Questions are generated by a fast LLM call (Gemini Flash) with the user's relevant nodes as context.
- **Example output:** *"Last Thursday, something made you emotional mid-sentence while talking about Alex. Do you understand that now?"* / *"You've noted that Rohan's snub bothered you but you called it silly. What was it really about?"*

## Multi-Hop Traversal Examples

**Example 1: Tracing a belief shift**
`Query("How did my view on mentorship change?")`
1. Vector retrieve `BeliefNode` matching "mentorship". Returns `bel_v2` ("Mentorship must be actively sought").
2. Graph traverse `bel_v2 -[evolved_from]-> bel_v1` ("Mentorship happens organically").
3. Graph traverse `bel_v2 -[decided_by]-> d_001 -[decided]-> ep_2026_06_12`.
4. Result: Context includes the old belief, the new belief, and the specific episode (Alex interaction) that triggered the shift.

**Example 2: Analyzing a relationship**
`Query("Am I spending too much time seeking external validation from X?")`
1. Vector retrieve `PersonEntityNode` for "X".
2. Graph traverse `person -[mentions]<- observation -[contains]<- episode`.
3. Filter observations for type `SOCIAL_PERFORMANCE_STATE` or `INAUTHENTICITY_STATE`.
4. Result: Context includes only the episodes with X where the user exhibited those specific patterns.
